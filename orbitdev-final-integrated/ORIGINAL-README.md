# Портфолио — настройка за 15 минут

Статический сайт-портфолио. Добавление нового проекта = один JSON-файл, без вёрстки.
Генератор без зависимостей: нужен только Python 3 (проверено на 3.9 и 3.12).

```
data/profile.json        ← ты, услуги, цены, контакты
data/projects/*.json     ← по файлу на проект
static/style.css         ← оформление
build.py                 ← генератор
dist/                    ← готовый сайт (создаётся сборкой)
profiles/                ← тексты профилей для LaborX, Freelancehunt, Fiverr, Contra
```

---

## Шаг 1. Заполни свои данные

Открой `data/profile.json` и замени четыре заглушки:

| Заглушка | Где взять |
|---|---|
| `YOUR_NAME` | Имя или ник, которым подписываешься в заявках. Одно и то же везде — это уже бренд |
| `YOUR_GITHUB_USERNAME` | Логин GitHub |
| `YOUR_TELEGRAM` | Юзернейм в Telegram, без `@` |
| `YOUR_DEMO_BOT` | Юзернейм демо-бота (в `data/projects/01-gatekit.json`) |

Там же проверь:

- **`services`** — цены уже стоят те, что мы выбрали: $250–450 за установку, $500–800 за кастом. Меняй, если решишь иначе, но не занижай ниже $150: дешёвый прайс отпугивает нормальных заказчиков сильнее, чем дорогой.
- **`site.url`** — финальный адрес сайта. Без него не будет sitemap и og-тегов для превью в мессенджерах. Поставишь после шага 4.
- **`available`** — `true` / `false`. Рисует зелёную точку «открыт для заказов».
- **`contacts.email`** — уже стоит твой; поменяй, если хочешь отдельный рабочий.

Сборка сама предупредит, если заглушки остались.

## Шаг 2. Собери

```bash
cd portfolio
python3 build.py
```

Получишь `dist/` с четырьмя страницами: английская и русская главная, английский и
русский разбор кейса. Плюс `sitemap.xml`, `robots.txt`, `.nojekyll`.

## Шаг 3. Посмотри локально

```bash
python3 -m http.server -d dist 8000
```

Открой `http://localhost:8000`. Проверь на телефоне тоже — половина заказчиков откроет
ссылку с телефона.

## Шаг 4. Опубликуй

Подробно — в [DEPLOY.md](DEPLOY.md). Коротко: два бесплатных варианта.

**GitHub Pages** — проще и для разработчика выглядит уместнее: адрес вида
`твой_логин.github.io` сам по себе сигнал, что человек пишет код.

**Свой VPS и домен** — у тебя уже есть и то и другое. `voxeldropz.store` для
разработческого портфолио звучит не очень; лучше поддомен `dev.voxeldropz.store`.

Поставь итоговый адрес в `site.url`, пересобери, задеплой ещё раз.

## Шаг 5. Разложи ссылку по площадкам

В папке [`profiles/`](profiles/) лежат готовые тексты профилей под каждую площадку,
на английском и русском. Скопируй, вставь, поменяй ссылки. Это та же самая история
в четырёх форматах — так работает узнаваемость.

## Как добавлять новые проекты

См. [ADDING-A-PROJECT.md](ADDING-A-PROJECT.md). Если коротко: копируешь
`data/projects/01-gatekit.json` в `02-что-то.json`, меняешь содержимое, пересобираешь.
Сортировка по имени файла, поэтому `02-`, `03-` и так далее — свежее сверху ставь
меньшим номером.

## Что в этом портфолио сделано осознанно

Это не шаблон с маркетплейса, и вот чем оно отличается.

**Ни одного выдуманного факта.** Нет «50+ довольных клиентов», нет придуманных отзывов,
нет логотипов компаний, с которыми ты не работал. Есть один проект и проверяемые числа
по нему: 53 юнит-теста, 56 сквозных проверок, 5035 строк. Заказчик может открыть репо
и всё пересчитать. Один проверяемый факт стоит дороже десяти красивых.

**Кейс объясняет решения, а не перечисляет технологии.** «Python, aiogram, Docker» не
говорит ни о чём — такое пишут все. «У TRC20-перевода нет memo, поэтому каждый счёт
получает уникальную сумму» говорит, что человек думал. В разборе есть и честно
описанный баг, который нашёлся живым вызовом API: это выглядит сильнее, чем безупречная
история, потому что безупречным историям не верят.

**Раздел «когда это не нужно».** В кейсе прямо написано, кому Gatekit не подходит и что
у Telegram есть бесплатная нативная альтернатива. Это не слабость: в нише, где все
продают через выдуманную боль, готовность сказать «тебе это не нужно» — самый дешёвый
способ выглядеть тем, кому можно доверять.

**Async без созвонов вынесен как политика работы, а не спрятан.** Ты не будешь звонить —
значит об этом надо сказать первым и в позитивной формулировке: «апдейты текстом,
созвоны не нужны». Заказчику, который сам не любит звонки, это плюс.

**Статика, а не JavaScript.** Текст лежит в HTML, поэтому его индексирует поиск.
Портфолио, которое не находится поиском, работает только по прямой ссылке.

**Двуязычность из одного файла.** Одни и те же данные отдают английскую и русскую
версию. RU-заказчики с Freelancehunt и EN-заказчики с LaborX видят одинаково нормальный
сайт, а поддерживать надо один JSON.

## Чего тут намеренно нет

- **Аналитики и куки.** Не нужны, пока нет трафика, и добавляют баннер согласия.
- **Формы обратной связи.** Требует бэкенд или сторонний сервис. Кнопка в Telegram
  работает лучше: заказчик и так сидит в мессенджере.
- **Блога.** Пустой блог хуже отсутствующего. Появится, что писать — добавим.
- **Тёмной темы.** Один режим, сделанный хорошо, лучше двух сделанных наполовину.
